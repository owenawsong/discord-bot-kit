FROM WORKSHOP TO SERVER

Ship with evidence.
Keep your secrets local.

The simulator needs no bot token. A live deployment uses your Discord application, a test guild, and the same handlers.

03
  1. 01

    Create the application.

    In the Discord Developer Portal, create an application and bot. Install it in a dedicated test server with bot and applications.commands scopes.

    Open Developer Portal ↗
  2. 02

    Configure recipe permissions.

    The ticket recipe needs View Channel, Send Messages, Read Message History, Manage Channels and Manage Roles. Grant only those. Create a dedicated support role (not @everyone) and record its ID. Signup bots only need View Channel and Send Messages.

  3. 03

    Check the local environment.

    Copy .env.example to .env and add your bot token, application ID, test guild ID and, for tickets, support role ID. Keep .env out of Git.

    guildwright doctor
  4. 04

    Preview before registering.

    Inspect the command manifest first. Applying replaces this application's command list in the configured test guild.

    guildwright register --bot bot.mjsguildwright register --bot bot.mjs --apply
  5. 05

    Verify in Discord.

    Start the bot, exercise tickets with two real members and a moderator, restart it, and verify the archived channel's permissions. Run one bot process per state file.

    guildwright start --bot bot.mjs

The local suite is development evidence, not proof of production readiness. Check your actual server permissions, network failures and deployment before inviting users.
